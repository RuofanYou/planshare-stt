# RaidGlass Apple 交互规范

金色视觉语言保持稳定。本规范约束布局、节奏、直接操作、状态反馈和无障碍，所有新交互都应先满足这里的合同。

## 1. 信息层级与呼吸感

- 页面只保留一条清晰主路径：目标选择 → 当前上下文 → Top10 时间轴 → 次级筛选与导出。
- 选择器、摘要、工具栏和内容各自成组，组内紧凑，组间使用更大的 4px 倍数间距。
- 主要容器允许内容自然增高；禁止为了塞进首屏压缩行高、控件高度和文字。
- 桌面端突出横向时间轴；430px 窄屏将横向滚动限制在时间轴内部，页面本身不得横向漂移。
- 固定玩家列与时间轴行严格同高、同序、同滚动上下文，任何数据长度都不能错位或叠行。

## 2. 直接操作

- 时间轴支持鼠标和触控拖动、触控板水平滚轮、Shift + 垂直滚轮平移。
- 普通垂直滚轮继续滚动页面，避免抢夺用户意图。
- 指针缩放以指针位置为锚；工具栏缩放以可视区域中心为锚。
- `+`、`-`、`0` 和左右方向键只在时间轴或工具栏拥有焦点时生效。
- 所有缩放和平移都受内容边界约束，松手后的惯性短、可预测、可随时被下一次输入打断。

## 3. 反馈与动效

- 点击、按压、复制、切换难度和打开面板必须在首次绘制内产生可见反馈。
- 通用按压比例为 `0.965`；释放、快速弹性和表面过渡由全局 motion token 提供，组件不得私自定义另一套节奏。
- 切换目标时保留旧时间轴，直到新目标通过身份校验并可提交；加载状态不得清空可用内容。
- 复制动作具备进行中、成功、失败三态，反馈文案与当前目标绑定，切换目标后旧反馈不得串入。
- `prefers-reduced-motion` 开启时关闭惯性、投影和回弹位移，保留即时状态反馈。

## 4. 状态与错误

- 新鲜数据使用稳定的成功状态；`stale` 明确显示“数据已过期”，旧排行仍可操作。
- 排行缺失、状态损坏或身份错误使用统一错误面板，禁止空数组、HTML 错误页和其他目标数据混入。
- 目标切换、请求接收、身份接受/拒绝、复制开始/成功/失败等关键节点写结构化诊断日志，字段名保持稳定。
- 页面刷新后 URL 恢复首领、专精、难度和指标；URL 是分享与恢复的唯一权威。

## 5. 控件与无障碍

- 桌面控件最小高度 40px，触控命中区最小 44px。
- 所有真实控件支持键盘操作，使用统一焦点环；禁用态仍可辨认文字。
- 对比度门禁覆盖动作按钮、危险/过期状态、页脚和主要正文。
- Modal 与窄屏 sheet 使用同一生命周期：打开后聚焦、Esc 关闭、焦点回到触发控件、背景不可误触。

## 6. 验收

每次生产交互变更至少验证：

1. 1440px 桌面和 430px 窄屏。
2. 目标选择、难度和指标切换。
3. 时间轴拖动、缩放、键盘和 reduced motion。
4. 筛选、复制反馈、逐行 WCL 链接。
5. 阵容搜索与 URL 刷新恢复。
6. stale、首次缺数据、请求失败和重复快速切换。
7. 控制台、同源请求、图片资源和布局几何零异常。

自动化门禁通过后仍需查看真实 Preview 的桌面与窄屏截图。用户明确验收后才记录视觉通过。
