# STT 写作示例与排错

以下示例用于确认结构和组合方式。实际 Boss 时间、人员和技能必须来自模板或玩家资料。

## 12.1 简称对话

用户：`帮我写 M2 的战术方案`

正确推进：

> 明白，M2 是 12.1 烈毒之渊二号 Boss 陵寝哨兵，史诗难度，我会按团队方案处理。我先读取内置模板。你希望先做完整基础时间轴，还是重点安排团队减伤？我推荐先做完整基础时间轴。

此时 Boss、团本、难度和团队用途均已确定，不再重复询问。`M+2` 才表示大秘境 2 层。

## 团队基础方案

```stt
[方案]
名称 = 团队基础示例
作者 = 团长

[人员]
坦克1 = 张三
治疗1 = 李四

[时间轴]
{time:00:10}{BOSS}{spell:123456}
{time:00:20}{所有人}分散
{time:00:30}{坦克1}换坦 {治疗1}注意坦克
```

## 同一时间不同 segment 参数

参数作用于所在 segment。治疗提前 8 秒、坦克提前 3 秒时，可以保留在同一行：

```stt
[方案]
名称 = 不同提前量示例
作者 = 团长

[人员]

[时间轴]
{time:00:30}{治疗}{sr:8}准备抬血 {坦克}{sr:3}准备换坦
```

## 主备与分组

```stt
[方案]
名称 = 人员映射示例
作者 = 团长

[人员]
主治疗 = 小明,小李
辅助治疗 = 老王
左侧组 = 主治疗 辅助治疗

[时间轴]
{time:00:20}{左侧组}左侧集合
{time:00:30}{主治疗}{治疗}开启减伤
```

逗号表示主备，只会选中一人；空格表示分组，组内人员都会展开。

## 人名与专精重名

```stt
[方案]
名称 = 同名人员示例
作者 = 团长

[人员]
DH1 = 噬灭
增辉1 = 增辉
右边 = DH1 增辉1 小明

[时间轴]
{time:00:10}{右边}右边集合
{time:00:20}{噬灭,增辉}专精集合
{time:00:30}{所有人}全团集合
```

第一条提醒指定三名玩家，第二条按专精筛选，第三条提醒全团。人员定义可以嵌套引用，但最终值只表示名字；`这组专精=噬灭 增辉` 也表示两个人名。旧方案若把人员变量当作条件别名，应将对应条件直接写进正文。

## 个人方案

```stt
[方案]
名称 = 恢复德个人示例
作者 = 玩家

[人员]

[时间轴]
{time:00:25}{spell:22812}开树皮
{time:00:50}{spell:740}开宁静
```

个人方案无受众事件只提醒本人。技能时间仍需按实际 Boss 和个人安排调整。

## 进度条与技能序列

```stt
[方案]
名称 = 显示效果示例
作者 = 团长

[人员]

[时间轴]
{time:00:40}{bar:5/<3,tick:5/3,spell:123456,label:<准备/释放>}{所有人}准备处理机制
{time:01:00}{tl:740,633<圣疗>,回响}{治疗}按顺序交技能
```

## 常见误写修复

同时提醒两个人：

- 误写：`{张三,李四}集合`
- 正确：`{张三}{李四}集合`

玩家或槽位同时满足小队条件：

- 误写：`{奶德1+g1}集合`
- 正确：`{奶德1}{g1}集合`

同一行给不同对象不同 `ct`、`sr` 或音效时，每个参数跟在自己的受众后面：

例如：`{time:00:30}{治疗}{ct:5}抬血 {坦克}{ct:3}换坦`。

多个 segment 之间的空格只用于阅读，不改变参数归属。

停用一条事件：

- `#`、`--` 和 `//` 都不是通用注释符。
- 移除该行或移除有效 `{time:...}`，不要依赖行首符号。

多人、职责和条件：

- `{治疗+牧师,治疗+圣骑士}` 表示两组“同时满足”条件之间取或。
- `{治疗}{张三}` 混合组条件和玩家名时，需要同时通过名字匹配。
- `{神圣}` 会匹配神圣牧师和神圣圣骑士；需要使用 `{神圣+牧师}` 或 `{神圣+圣骑士}` 消歧。

## 最小修复原则

1. 复制原方案并逐行定位问题。
2. 保留用户给出的时间、人员、分工、Spell ID 和正文。
3. 只修导致错误的区块、括号、时间、受众、槽位或行级参数。
4. 必须拆行时复制原时间和对应受众，不顺手改写其他正文。
5. 交付时列出修改过的行和原因。
